# 对比示例：差简历 vs 好简历

## 示例 1：项目经历

### ❌ 差版本

```
项目经历
─────────────────────────────────────────────────────────────────
校园二手交易平台 | 2023.03 - 2023.06
• 用 Vue.js 做了一个校园二手交易平台
• 负责前端开发
• 实现了商品列表、购物车等功能
• 项目上线了，挺多人用的
```

**问题**：
- 没有 STAR 结构
- 没有量化数据
- "挺多人用"太模糊
- "负责前端开发"没有体现个人贡献
- 缺少技术亮点

---

### ✅ 好版本

```
项目经历
─────────────────────────────────────────────────────────────────
校园二手交易平台 | 前端负责人 | 2023.03 - 2023.06
• 技术栈：Vue.js 3 + Vuex + Element Plus + Axios
• 背景：选修《软件工程》课程，小组需在 8 周内完成一个校园交易平台
• 行动：
  - 独立负责前端开发，实现商品浏览、购物车、订单管理 3 个核心模块
  - 封装 5 个通用组件，代码复用率提升 40%
  - 实现响应式布局，移动端适配率达 100%
• 成果：项目按时上线，2 个月内注册用户 2000+，日均交易 50+ 笔，获课程优秀项目奖
```

**优点**：
- STAR 结构清晰
- 量化数据具体
- 突出个人贡献
- 有技术亮点

## 总结对比

| 维度 | 差简历 | 好简历 |
|-----|-------|-------|
| 结构 | 流水账 | STAR 结构 |
| 数据 | 模糊描述 | 量化数据 |
| 贡献 | "我们做了" | "我独立完成" |
| 技能 | 堆砌、精通太多 | 分类、标注程度 |
| 评价 | 空话套话 | 具体事例 |
| 格式 | 随意 | 专业规范 |
